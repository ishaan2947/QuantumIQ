# Deploying QuantumIQ on free tiers

Frontend on **Vercel**, backend on **Render**. Everything below fits inside the
free plans; the places where that costs you something are called out honestly at
the bottom.

```
  Browser
    │
    ├─ Vercel (static)   quantumiq.vercel.app
    │    landing page, simulator, Bloch sphere      ← all client-side, always works
    │
    └─ Render (web)      quantumiq-api.onrender.com
         /api/demo/chat  ← gpt-4o-mini, rate limited
         /api/auth, /api/circuits, /api/simulate, /api/chat
              │
              └─ Render Postgres (free)
```

The split matters: the landing page's simulator, Bloch sphere and measurement
panel run entirely in the browser (`src/lib/quantumSim.ts`). They do not call
Render at all, so a cold or even dead backend never produces a broken-looking
landing page — only the tutor needs the server.

---

## 1. Backend on Render

The repo ships a blueprint at [`render.yaml`](../render.yaml).

**Dashboard → New → Blueprint → select this repo.** It provisions the web
service and a free Postgres instance.

To do it by hand instead:

| Setting | Value |
| --- | --- |
| Root directory | `backend` |
| Runtime | Python 3.11 |
| Build command | `pip install --no-cache-dir -r requirements.txt` |
| Start command | `uvicorn app.main:app --host 0.0.0.0 --port $PORT --workers 1` |
| Health check path | `/api/health` |

**`--workers 1` is required, not just cheap.** The demo's rate limiters keep
their counters in process memory (`app/core/rate_limit.py`). A second worker
keeps a second set of counters, which silently doubles every limit.

### Environment variables

Set these in the Render dashboard. Only two have no sensible default:

| Variable | Value | Notes |
| --- | --- | --- |
| `OPENAI_API_KEY` | `sk-…` | Required for the demo tutor |
| `CORS_ORIGINS` | `https://your-app.vercel.app` | Your Vercel production domain |
| `DATABASE_URL` | *(auto)* | Wired by the blueprint |
| `SECRET_KEY` | *(auto)* | Generated by the blueprint |

Everything else — the demo limits, the model, the daily budget — has a working
default in `app/core/config.py`. The full list with explanations is in
[`backend/.env.example`](../backend/.env.example).

Preview deployments are handled automatically: `app/main.py` allows any
`*.vercel.app` origin via regex, so branch previews work without editing
`CORS_ORIGINS`. Set `ALLOW_VERCEL_PREVIEWS=false` if you'd rather pin origins
exactly.

## 2. Frontend on Vercel

**New Project → import the repo → set Root Directory to `frontend`.**
[`frontend/vercel.json`](../frontend/vercel.json) supplies the framework preset,
the SPA rewrite (so `/lab` deep-links don't 404) and immutable caching for
hashed assets.

### Environment variables

| Variable | Value |
| --- | --- |
| `VITE_PUBLIC_API_URL` | `https://quantumiq-api.onrender.com` |
| `VITE_GITHUB_REPO_URL` | `https://github.com/ishaan2947/QuantumIQ` |

> **Do not use `VITE_API_URL` here.** That name is already taken by
> `docker-compose.yml`, where it is the *dev server's* proxy target
> (`http://backend:8000` — a hostname that only resolves inside the Docker
> network). Vite exposes every `VITE_`-prefixed variable to the browser, so
> reusing it would point production at an unreachable host. The browser-facing
> origin is `VITE_PUBLIC_API_URL`.

Leave `VITE_PUBLIC_API_URL` unset locally: `vite.config.ts` proxies `/api` to
`localhost:8000`, so there's no CORS involved in development.

## 3. Free-tier limits worth knowing about

### Render spins the service down after ~15 minutes idle

This is the big one. A cold start takes roughly **50 seconds**, and on a
portfolio site most visits arrive at a cold instance.

What's already built to handle it:

- **The simulator never touches the backend.** Circuit building, the Bloch
  sphere, probabilities and step-through all run in the browser. A visitor can
  use most of the demo while the server is still booting.
- **The landing page pings `/api/health` on mount** (`warmUpBackend()` in
  `services/demoApi.ts`). The wake-up starts while the visitor is still reading
  the hero, so by the time they scroll to the tutor it is usually warm.
- **The tutor explains itself.** If a request runs past 4 seconds, the chat
  shows "the demo backend sleeps when idle — the first reply can take up to a
  minute" instead of an anonymous spinner.

**If you want to eliminate it entirely**, an external pinger (cron-job.org,
UptimeRobot) hitting `/api/health` every 10 minutes keeps the instance awake.
Read the trade-off before doing it: Render's free tier gives **750 instance
hours per month across all your free web services**, and a month is ~730 hours.
Keeping one service awake 24/7 consumes essentially the entire allowance, so
this works only if this is your only free Render service. The warm-up ping is
the better default.

### Render's free Postgres expires

Free databases are deleted after a limited period (check Render's current
terms — it has changed). When that happens, auth and saved circuits break.

The landing page, the simulator and the demo tutor **keep working**: none of
them touch the database, and `app/main.py` deliberately treats an unreachable
database at startup as a logged warning rather than a fatal error, so the
service still boots and serves everything that doesn't need tables.

### Rate limit counters reset when the instance restarts

The in-memory limiters lose their state on a deploy or a spin-down, so a
visitor who waits out a cold start gets a fresh five messages. That is a fair
trade for not running Redis. If it ever matters, `SlidingWindowLimiter`,
`SessionCounter` and `DailyBudget` are small and self-contained — swapping them
for an Upstash Redis (also free) is a contained change.

### OpenAI is the one thing that isn't free

The demo is bounded on four axes so this stays a rounding error:

| Guard | Default | Effect |
| --- | --- | --- |
| `DEMO_SESSION_LIMIT` | 5 | Messages per browser session |
| `DEMO_IP_BURST_LIMIT` | 6 / min | Stops scripted hammering |
| `DEMO_IP_LIMIT` | 15 / hour | Stops one network draining the budget |
| `DEMO_DAILY_BUDGET` | 300 / day | Hard ceiling across all visitors |

The demo uses `gpt-4o-mini` with `max_tokens=400` and at most 6 turns of
history, so a message costs roughly **$0.0003**. The daily budget caps spend at
about **$0.09/day** — under **$3/month** even if the demo is saturated every
single day. Lower `DEMO_DAILY_BUDGET` if you want a tighter bound; set
`DEMO_ENABLED=false` to turn the tutor off entirely while leaving the simulator
live.

The signed-in tutor is a different thing — it runs the full agent loop against
`gpt-4o` with tool calling, which is exactly why it sits behind a login and the
demo does not use it.

### Vercel bandwidth

The free plan includes 100 GB/month. The hero image is 153 KB and Three.js is
code-split out of the landing page's first paint (it loads only when the demo
section mounts), so a page view costs roughly 300–400 KB. That is comfortably
into six figures of monthly visits.

## 4. Verifying a deployment

```bash
# Backend is up (this is also what wakes it)
curl https://quantumiq-api.onrender.com/api/health

# Demo is configured — "enabled": false means OPENAI_API_KEY is missing
curl "https://quantumiq-api.onrender.com/api/demo/status?session_id=test"

# CORS actually allows your frontend
curl -sI -X OPTIONS https://quantumiq-api.onrender.com/api/demo/chat \
  -H "Origin: https://your-app.vercel.app" \
  -H "Access-Control-Request-Method: POST" | grep -i access-control-allow-origin
```

If the tutor returns 503 with `"limit_type": "unconfigured"`, the API key isn't
set on Render. If the browser console shows a CORS error, `CORS_ORIGINS` doesn't
match your Vercel domain.

## 5. Local development

Unchanged — `docker compose up` still brings up the whole stack, and the landing
page is at `/`. To run the pieces directly:

```bash
# Backend
cd backend
pip install -r requirements.txt
cp .env.example .env        # set OPENAI_API_KEY
uvicorn app.main:app --reload --port 8000

# Frontend
cd frontend
npm install
npm run dev                 # http://localhost:5173
```

Leave `VITE_PUBLIC_API_URL` unset locally so the Vite proxy handles `/api`.
